# 表情按「表情」发 (Sticker Send As Emoji) 🌠

让机器人发送的表情包以 QQ 原生**「表情」形式呈现（紧凑小图展示、可长按收藏）**，告别撑满气泡的巨幅大图！
能与 `meme_manager` 等表情插件无缝配合，无需修改现有表情包插件的任何代码。

---

## ❓ 为什么需要这个插件？

### 痛点根因
在 QQ 个人号（基于 OneBot V11 / NapCat / Lagrange / LLOneBot 等协议端）中，图片消息段依靠一个叫 `sub_type` 的字段区分展示类型：
- **`sub_type = 0`**：普通图片（客户端按原图尺寸大图渲染；即便是一张 300×300 的表情图，也会撑满对话气泡变成大图）；
- **`sub_type = 1`**：表情贴纸（客户端按原生表情包渲染，小而紧凑，背景自适应透明，**手机端支持长按一键添加到表情收藏**）。

AstrBot 底层适配器在构建 OneBot 图片消息段时，原生只序列化了 `file` 字段，**从未附带过 `sub_type` 字段**。协议端于是默认按 `0` 处理 —— 这就是机器人发送表情包总变成一张大图的根源。

---

## ✨ 核心特性

1. **表情以原生「表情」展示**：
   在消息分发阶段拦截并将图片段标记为 `sub_type = 1`，小巧美观、可长按收藏。
2. **与 `meme_manager` 零侵入配合**：
   自动识别 `meme_manager` 的图库目录、临时表情文件、混合消息与独立发送链路，直接生效，无需对 `meme_manager` 做任何修改。
3. **智能识别，绝不误伤普通图片**：
   支持三种识别模式：
   - `smart` (默认推荐)：自动识别表情插件、GIF 动图与打标图片；普通照片与 AI 绘画大图不受影响；
   - `meme_only`：仅对来自表情管理插件的图片生效；
   - `all_images`：所有图片一律按表情发送（适合纯表情包机器人）。
4. **防御性异常安全隔离**：
   所有消息拦截均设有兜底保护机制。若遇到任何未知数据或异常，自动降级为普通图片发送，绝不阻断聊天。
5. **支持完整热重载**：
   生命周期严格管理，卸载或重载时完整还原底层方法，零副作用残留。

## ⚙️ 配置说明 (`_conf_schema.json`)

可在 AstrBot WebUI 插件管理面板中可视化配置：

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| **`enabled`** | `bool` | `true` | 是否启用表情发送增强。关上后恢复原样大图。 |
| **`sub_type`** | `int` | `1` | OneBot V11 协议表情标记值。1 为表情，0 为普通大图。 |
| **`mode`** | `string` | `smart` | 识别模式：`smart` (智能识别) / `meme_only` (仅表情插件) / `all_images` (所有图片) |
| **`treat_gif_as_emoji`** | `bool` | `true` | 智能模式下是否将所有 `.gif` 动图视为表情包。 |
| **`extra_dirs`** | `list` | `[]` | 自定义表情目录路径，目录内的图片发送时将自动转为表情。 |
| **`debug`** | `bool` | `false` | 是否在控制台打印拦截与标记的调试日志。 |

## ⌨️ 管理指令

指令组采用 `/semoji`（支持别名 `/emojisticker`、`/sticker_emoji`、`/表情样式`），与 `sticker_sense` 插件自带的 `/sticker` 彻底隔离，绝不冲突：

- `/semoji status`（或 `/emojisticker status`）：查看插件当前运行状态、补丁是否挂载、识别模式及表情目录索引。
- `/semoji toggle`：快速开启或关闭表情发送模式（状态将通过 KV 存储持久化，重启不失效）。
- `/semoji test`：发送一张内置测试小表情，验证 QQ 客户端是否以表情样式展示。
